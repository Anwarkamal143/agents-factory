## Context
MVP behaviour is proven on happy and scripted-failure paths. Production readiness needs random faults, volume, and safe concurrency on one repository. Read SPEC-01 "Event log and store" and the T-16 invariant checker.

## What to build
- **Fault-injection harness** with a seeded RNG: ENOSPC on event append, adapter crash mid-attempt, adapter hang, verification flake, slow disk, clock jump, kill -9 at random event boundaries.
- **Soak runner** `tests/soak`: N runs (default 100) with randomized scenarios and faults; after each run assert the T-16 invariants, log integrity, and that **every side effect has a preceding `policy.decision` event**.
- **Concurrent runs per repository:** two runs may execute against the same project at once. Delivery is serialized by a repository-level delivery lease; a base branch that moved triggers T-10's re-integrate-and-re-verify.
- **`factory gc`:** dry-run by default; lists worktrees and branches eligible for removal (completed/canceled runs older than N days); writes a recovery file; never removes anything belonging to a non-terminal run or an unmerged branch.
- **Flaky verification policy:** a single automatic retry of a failing check is allowed only if configured, is recorded as `verification.flaky`, and never converts a failure into a pass silently.

## Demo path
```
$ pytest -m soak --soak-runs 100 --seed 12345       # nightly; prints seeds of any failing run
$ pytest -m "soak and smoke"                         # 20 runs in default CI
$ factory gc                                         # dry run: lists candidates + recovery file path
```

## Acceptance criteria
- [ ] 100 seeded soak runs finish with **zero** invariant violations, zero corrupted logs (every log passes the integrity verifier) and zero side effects lacking a prior policy decision; the PR records the seed and result.
- [ ] A failing soak run prints its seed and the command to reproduce it; re-running that seed reproduces the same event sequence.
- [ ] ENOSPC during append fails the run loudly with a non-zero exit and leaves a recoverable log (resume after freeing space completes).
- [ ] Two concurrent runs on one repo both complete; their deliveries are serialized (second delivery's integration shows a re-verify against the moved base); no lost updates to the base branch.
- [ ] `factory gc` dry run changes nothing (tree hash); with `--apply` it removes only terminal-run worktrees past the age threshold, writes the recovery file, and refuses to touch an unmerged branch.
- [ ] A flaky check (fails once then passes) is retried once only when configured and a `verification.flaky` event exists; with retries disabled it fails the task.

## Implementation notes
- Seeds are logged at the start of every soak run; never use wall-clock randomness.
- The delivery lease reuses the T-03 lease mechanism at repository scope.
- Slow tests carry markers `soak`; the smoke subset is fast enough for default CI.

## Out of scope
Distributed workers; engine process concurrency within one run; load testing against real harnesses.

## Decisions & questions
Flag, do not decide: whether soak failures should block releases (default: yes for any invariant violation).

## Security & failure notes
Faults must never be able to produce an unauthorized side effect; the audit assertion "side effect implies prior decision" is the guard. `gc` is destructive: dry-run default, recovery file, and a test proving it refuses non-terminal runs.

## Definition of done
Criteria checked; soak result pasted in the PR; nightly workflow added; GLOSSARY updated (Soak run, Delivery lease); runbook `docs/operations.md` for recovering from each injected fault.
