## Context
One real adapter proves nothing about neutrality. A second adapter (the other major harness, or the generic stdin/stdout CLI path) proves the contract. Read T-12 (contract suite, degradation) and T-13 (what a real adapter needs).

## What to build
- A second adapter package passing the T-12 contract suite (`real`-tagged; transcript-replay variant in default CI).
- **Parity suite:** run the same scenario set (success, flaky, malformed output, timeout, cancel, permission denial) through both real adapters (and the fake) and assert **equal final task/run states and equal event types and ordering** except `usage` and timing fields.
- Degradation table for this adapter documented in `docs/adapters/<name>.md` (what it cannot do, what autonomy cap results).
- `factory adapter probe` lists both adapters with capabilities.

## Demo path
```
$ factory adapter list              # fake, <first>, <second>
$ pytest -m real tests/parity       # nightly/manual
```

## Acceptance criteria
- [ ] The second adapter passes the contract suite (replay variant in CI, live variant tagged `real`).
- [ ] The parity suite passes: identical final states and event-type sequences across `fake`, first and second adapter for every scenario (comparison ignores `usage` and timestamps, asserted explicitly).
- [ ] Any capability this adapter lacks produces a `capability.degraded` event and the documented autonomy cap; none is silently dropped.
- [ ] Swapping `adapter:` in `project.yaml` between the two requires no other config change (test switches adapters on one fixture).
- [ ] No harness name appears in `core.*` modules (import and string lint test).

## Seams
**Adapter contract** and **Engine API/CLI**.

## TDD plan
1. Transcript parser fixtures for the new adapter.
2. Permission mapping table.
3. Contract suite via replay.
4. Parity runner over the scenario set (start with fake vs fake to prove the comparator).
5. Core-purity lint.
