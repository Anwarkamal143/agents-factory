## Context
The predecessor's installer replaced whole directories with `rm -rf` plus copy (an incident deleted 190 unrelated entries) and shipped through an unverified `curl | bash`. Here every managed file is tracked with a hash, upgrades are explicit, and releases are verifiable. Read DEC-05's resolution (names, license, channel) and `docs/analysis/13-installation-and-developer-experience.md`.

## What to build
- **Lockfile** `.factory/factory.lock`: version, and for each managed file `{path, sha256}`; managed files live under `.factory/managed/`; project-owned files (`project.yaml`, `overrides/`) are never touched.
- **`factory upgrade --plan`:** shows file diffs, schema migrations and drift (managed files edited by hand); `factory upgrade` applies it, writes a backup `.factory/backups/<timestamp>/`, and refuses while any run holds a live lease.
- **`factory rollback`:** restore the previous managed set from the backup; verified by hashes.
- **`factory uninstall [--keep-state]`:** removes only files listed in the lock; prints the list first; never deletes unrelated files.
- **`factory doctor`** extension: reports drift (managed file hash mismatch) without fixing it.
- **Release pipeline:** tag-triggered workflow builds the artifact, writes `SHA256SUMS`, attaches both to the GitHub Release; `factory verify-install SHA256SUMS` checks a downloaded artifact. (Signing method per DEC-05 resolution; if unresolved, ship checksums only and note it.)

## Demo path
```
$ factory upgrade --plan        # file diffs, migrations, drift list
$ factory upgrade && factory rollback
$ factory uninstall             # lists exactly what it will remove, asks to confirm
```

## Acceptance criteria
- [ ] **Regression for the predecessor incident:** a project directory containing 190 unrelated files next to `.factory/` survives `upgrade`, `rollback` and `uninstall` with every unrelated file byte-identical (hash set compared).
- [ ] Editing a managed file by hand is reported as drift by `doctor` and by `upgrade --plan`; `upgrade` refuses without `--force` and preserves a copy.
- [ ] `upgrade` is refused while a run's lease is live (exit 4); allowed once the lease is released.
- [ ] `rollback` restores the exact previous managed file hashes recorded in the backup.
- [ ] `uninstall` removes only lockfile-listed paths and leaves `project.yaml`, `overrides/` and `state/` unless `--purge` is given.
- [ ] `verify-install` rejects an artifact whose hash differs (exit 2) and accepts the correct one; the release workflow output includes `SHA256SUMS` (checked by a workflow lint test).

## Implementation notes
- All file operations go through one `ManagedFiles` helper that can only touch paths present in the lock or the declared managed root.
- Backups are copies, not moves; rollback never deletes the backup it restored from.
- The on-disk lock format is versioned (one-way door).

## Out of scope
Auto-update checks, package-manager integration (PyPI), multi-version side-by-side installs.

## Decisions & questions
DEC-05 supplies names and signing choice. If signing keys are required and unresolved, ship checksums and open a follow-up issue labelled `needs-info`.

## Security & failure notes
Deletion is the dangerous verb: path allow-listing, dry-run first, tests with hostile symlinks inside `.factory/managed/`. Never follow symlinks during removal.

## Definition of done
Criteria checked; `docs/installing.md` written; ADR for the lock format if it clears the bar; Merge Danger section calls out the one-way format and names the rollback.
