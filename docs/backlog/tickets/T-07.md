## Context
The predecessor judged file overlap with an LLM pre-flight and fixed conflicts late with a rebase pass. Here overlap is **declared** (`write_set` per task, validated in the plan) and enforced by the scheduler. Read SPEC-01 "Scheduler".

## What to build
- Run up to `max_parallel` (default 4) ready tasks concurrently, each in its own workspace directory.
- Two tasks may run at the same time only if their **write sets are pairwise disjoint**. Overlapping tasks are serialized in plan order.
- **Overlap rule (conservative):** write sets overlap if any entry is equal, one is a directory prefix of the other, or two glob patterns could match the same path (when unsure, treat as overlapping). An **empty** write set means "unknown": the task is serialized against everything.
- Single event writer: concurrent attempts post events through one queue so `seq` stays gapless and ordered by arrival.
- Fake adapter scenario `barrier`: attempt blocks until N attempts have started (proves concurrency without sleeps).
- Starvation guard: oldest ready task first.

## Demo path
```
$ factory run --plan fixtures/two_disjoint.json --adapter fake --project fixtures/barrier
run completed (2/2 tasks succeeded)           # both attempt.started precede both attempt.finished
$ factory run --plan fixtures/two_overlapping.json ...
# second attempt.started occurs only after the first attempt.finished
```

## Acceptance criteria
- [ ] Two disjoint tasks with `max_parallel=2`: the event log shows two `attempt.started` before any `attempt.finished` (barrier scenario, no sleeps).
- [ ] Two tasks with write sets `["src/a/**"]` and `["src/a/b.py"]` (glob contains path) never overlap in time: second `attempt.started` seq > first `attempt.finished` seq.
- [ ] `max_parallel=1` serializes everything regardless of write sets.
- [ ] A task with an empty `write_set` runs alone (no other attempt overlaps it).
- [ ] 50 independent tasks, `max_parallel=4`: `seq` is gapless 1..N, never more than 4 attempts open at once (computed from the log), final state `completed`.
- [ ] Overlap table (literal pairs, both orders) is correct: equal paths, dir prefix, glob vs path, glob vs glob (`*.py` vs `a*.py` overlap), disjoint dirs (no overlap).

## Seams
**Engine API/CLI** and, for the overlap predicate only, the **public function** `write_sets_overlap(a, b)` (declared as a seam in the PR since it is a pure public rule worth a table-driven test).

## Implementation notes
- Use threads or asyncio, whichever DEC-01's toolchain makes simplest; the **only** shared mutable state is the scheduler's view, guarded; the event queue has one consumer.
- Never decide overlap from file contents; only from declared sets.
- Open-attempt invariant check is a test helper over the log, reused by T-18.

## Out of scope

## Decisions & questions

## Security & failure notes
Declared write sets are a scheduling input, not a security boundary (that arrives with T-10 diff verification and T-17). A task that writes outside its declared set is a **finding** once T-10 lands.
