## Context
Replaces the temp-directory workspaces with real git isolation and adds the only code path allowed to change the user's branch. This ports the safety semantics of the predecessor's merge gate (verify on the current base, pin the reviewed head, serialize merges) into the engine, while fixing its weakness that any agent could run a bare merge. Read SPEC-01 "Task state machine" (`integrating` rows) and "Policy and autonomy". Local git only (DEC-04 default); no GitHub.

## What to build
- **Task worktrees** under `.factory/state/<run>/worktrees/<task>` on branch `factory/<run>/<task>` created from the recorded base commit; verification runs in the worktree.
- **Write-set check as an engine-run verification check** named `write-set`: compare `git diff --name-only <base>...HEAD` with the declared `write_set`; any path outside it => `verification.recorded(passed=false)` and the task returns to `running` with reason `undeclared_write`.
- **Integrator:** in a scratch worktree, apply succeeded tasks onto `factory/<run>/integration` in plan order using `git merge --no-ff --no-commit`; conflict => abort, task `integrating -> running` with the conflict file list as context (a rebase task); clean => commit with trailer lines `Task: T-n` and `Run: R-...`, then **re-run the full verify set on the integrated head**.
- **Delivery (`deliver.merge`, engine only, policy-gated, T-09 approvals):** if the base branch moved since the run started, re-integrate onto the new base and re-verify; then fast-forward the base (`--ff-only`). If the base branch is checked out, require a clean working tree (else exit 7, nothing changed); if not checked out, update the ref atomically.
- **Cleanup:** remove task worktrees after integration; keep failed ones; never delete unmerged branches.
- All engine git commands run with hooks and filters disabled (`core.hooksPath` to an empty dir, no submodule recursion, `GIT_CONFIG_NOSYSTEM=1`).

## Acceptance criteria
- [ ] Two tasks touching different files integrate; base branch history is linear (no merge commits) and contains exactly two new commits whose messages have the literal trailers `Task: T-1`/`T-2` and `Run: <id>`.
- [ ] Two tasks editing the same lines: the second returns `integrating -> running` with the conflicting path in its context; after the fake agent resolves it, the run completes.
- [ ] A task changing a file outside its `write_set` fails the `write-set` check (event shows the offending path) and goes back to `running`; it does not reach `reviewing`/`integrating`.
- [ ] If another commit lands on the base during the run, delivery re-integrates, re-runs verification (a new `verification.recorded` with the **new** base hash precedes `deliver`), and only then fast-forwards.
- [ ] Delivery with a dirty working tree on the checked-out base exits 7 and leaves the tree and refs byte-identical (hash before/after).
- [ ] Before delivery, the user's checked-out branch and working tree are never modified (hash before/after, sampled at every event during a run).
- [ ] A malicious repo hook (`post-checkout` writing a marker file) and a `.gitattributes` filter do **not** execute during any engine git operation (marker absent).
- [ ] Without a granted approval at L2, `deliver.merge` never changes refs (negative test).

## Implementation notes
- Record base commit and integration head in events (`artifact.recorded` with commit ids).
- Serialize integration with the existing single-writer discipline; integration is the one place two tasks meet.
- Prefer `git update-ref` with an expected old value for atomicity when the base is not checked out.
- Policy: `git.write` by engine inside `.factory/state` is allowed; any git write outside it requires the explicit `deliver.merge` decision.

## Security & failure notes
This ticket executes `git` against **untrusted repositories**: hooks, filters, fsmonitor, `core.sshCommand` and similar config can run code, so engine calls pass `-c` overrides to neutralize them and set a minimal environment. Treat repo-local config as untrusted. One-way door: it changes the user's branch. Merge Danger must say so and name the guards (approval, clean tree, ff-only, re-verify).
