## Context
`agents-factory` is empty. Every later ticket is built by a fresh agent session that knows nothing but the repo, so the repo itself must carry the workflow: skills, tracker config, glossary, coding standards, templates, CI. Demo path: a new session can run `backlog.py next`, pick a ticket, and find everything it needs without asking you.

**Human prerequisites (verify first; if any is missing, comment on this issue with label `needs-info` and stop):**
1. The bundle in the delivered `repo-files/` directory has been committed to `main` as the initial commit (an empty repo cannot take a PR). It already contains `docs/agents/*`, `AGENTS.md`, `CLAUDE.md`, `GLOSSARY.md`, `CODING_STANDARDS.md`, `.github/*`, `labels.json`, `tools/backlog/`.
2. The labels in `labels.json` exist on GitHub (`gh label create` loop in `docs/agents/issue-tracker.md`).
3. The skills are installed (`npx skills@latest add mattpocock/skills`, or the Claude Code plugin) and `/setup-matt-pocock-skills` has been run once and its output matches `docs/agents/`.

## What to build
1. Toolchain files for DEC-01's choice (default: `pyproject.toml` with `uv`, `pytest`, `ruff`, `pyright` strict on `core` and `contracts`; empty `src` package `agents_factory` with a `--version` CLI stub).
2. CI workflow: lint, type-check, run the default test suite (excludes tests tagged `real`) on Linux and macOS; run `python tools/backlog/backlog.py validate` and its unit tests.
3. `LICENSE` per DEC-05 and a `README.md` (what it is, status "pre-MVP", how an agent picks a ticket: link to `docs/agents/ticket-runner.md`).
4. Check that the CLI name chosen in DEC-05 does not collide with an executable already on common PATHs (record the result in the PR).
5. Move the analysis package to `docs/analysis/` and the spec to `docs/spec/SPEC.md` if not already committed; add `docs/adr/0000-template.md` if missing.
6. `.gitignore` including `.scratch/` (review and PR scratch files), `.factory/state/`, `.backlog-map.json`, caches (the bundle ships one; verify and extend it for the chosen toolchain).
7. Policy files: `SECURITY.md` (how to report a vulnerability privately; no public issues for security reports), `CODEOWNERS` (maintainer owns `docs/agents/**`, `.github/**`, `docs/spec/**` and, once they exist, the policy and approval modules), `CONTRIBUTING.md` (one paragraph pointing at `AGENTS.md` and the ticket workflow).
8. Append the **sub-agent recursion guard** and the **skill name-clash note** to `AGENTS.md` if absent (text is in `docs/agents/review-protocol.md`).

## Acceptance criteria
- [ ] On a fresh clone, one documented command sequence (`uv sync`, lint, type-check, tests) passes on Linux and macOS in CI.
- [ ] `python tools/backlog/backlog.py validate` passes in CI and fails (non-zero) when a ticket file is made invalid (demonstrate once in the PR description, then revert).
- [ ] `AGENTS.md` contains the `## Agent skills` block pointing at `docs/agents/issue-tracker.md`, `docs/agents/triage-labels.md`, `docs/agents/domain.md`; `CLAUDE.md` is a one-line pointer to `AGENTS.md`.
- [ ] `GLOSSARY.md`, `CODING_STANDARDS.md`, `docs/spec/SPEC.md`, `docs/analysis/` exist and are linked from `README.md`.
- [ ] The PR template and the three issue templates render correctly on GitHub (screenshots or links in the PR).
- [ ] `SECURITY.md`, `CODEOWNERS` and `CONTRIBUTING.md` exist; `CODEOWNERS` paths are valid (GitHub shows no errors on the file).
- [ ] Branch protection checklist in `docs/agents/pr-protocol.md` is applied by a human and confirmed by a comment on this issue (agents cannot change repo settings).

## Out of scope
Any engine code beyond the `--version` stub; real tests (a single smoke test is enough); publishing a package; choosing hosting for docs.

## Definition of done
PR merged with `Closes #<this>`; CI green on `main`; a comment on this issue lists the exact verification commands run and links the PR; ticket-runner dry run performed (below).

## Dry run
Run `python tools/backlog/backlog.py next --json <fixture>` and then follow `docs/agents/ticket-runner.md` steps 1-3 on any `ready-for-agent` ticket **without implementing it**; paste the readiness report it would post. This proves the workflow is usable by a cold session.
