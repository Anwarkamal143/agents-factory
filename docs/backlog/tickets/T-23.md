## Context
Only if DEC-04 chose to support GitHub delivery. GitHub is a **projection** of engine state, never the source of truth: everything it shows can be rebuilt from the event log. The predecessor's GitHub-as-state design hit documented API quota incidents and non-atomic claims; avoid both. Read SPK-03's refusal-reason table.

## What to build
- `integrations.github` behind an integration interface: when `delivery: pr` is configured, push the integration branch (engine-only, policy-gated) and open a PR whose body is generated from the run (spec acceptance table, task list, verification evidence, findings, Mermaid flow); post status updates as a single edited comment.
- Merge refusal reasons from SPK-03 map to **task-level `blocked`** with the reason, not a whole-run halt.
- **Rate-limit discipline:** conditional requests, bounded retries (3) with backoff, response shape validation, and a local cache; quota exhaustion makes the integration `degraded` (the run continues locally) rather than halting.
- Auth via the `gh` CLI session or a token **by name**; never logged.
- Tests with recorded fixtures and a local stub server; no network in default CI.

## Demo path
```
$ factory run ... --delivery pr        # after approval: branch pushed, PR opened with generated body
$ factory status <run>                 # shows PR url and check status
```

## Acceptance criteria
- [ ] With the stub server, delivery pushes the integration branch and creates a PR whose body contains the acceptance table (literal rows for AC-1..AC-n) and the verification summary.
- [ ] For each refusal reason in SPK-03's table, the engine marks the task `blocked` with that reason and the run is not halted (one test per reason).
- [ ] Simulated 403 rate-limit and 5xx responses: at most 3 attempts, then the integration is `degraded` and the local delivery path still works; no event is lost.
- [ ] Deleting all GitHub state and re-running `factory status` reproduces the same engine state (projection is rebuildable).
- [ ] The token value never appears in logs, events or artifacts (scan).
- [ ] Without `delivery: pr`, no network call is attempted (stub server records zero requests).

## Seams
**Engine API/CLI** with a stub GitHub server; the integration interface is exercised through the engine.

## Security & failure notes
