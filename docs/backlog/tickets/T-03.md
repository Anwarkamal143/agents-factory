## Context
The event log format is a persistence contract users will depend on, so this ticket hardens it before anything else builds on it. Goal: `kill -9` at **any** event boundary, or a torn final line, never loses or duplicates state; `factory resume` continues. Read SPEC-01 "Event log and store" and "Task state machine".

## What to build
- **Lease:** exclusive lease file per run (create-exclusive; contains pid, host, start time, heartbeat). Live lease held by another process -> refuse. Stale lease (heartbeat older than TTL, default 30 s) -> takeover recorded as `lease.acquired` with `taken_over_from`.
- **Durable append:** each event line written then `fsync`; directory `fsync` after file creation.
- **Startup recovery:** truncate a torn final line; verify `seq` gapless and every `crc32`; mismatch in the middle of the file -> refuse with exit code 3 (`StateCorrupt`) and a message naming the first bad `seq`; never auto-edit the middle.
- **Snapshot:** written to a temp file, `fsync`, atomic rename; rebuilt from the log whenever missing, older than the log, or on schema-version mismatch (unknown future version -> refuse).
- **Idempotent transitions:** a replayed transition event whose `to` equals the current state is a no-op; a transition whose expected `from` does not match is rejected.
- **`factory resume <run>`:** continues a run; for every `attempt.started` without an `attempt.finished`, emit `attempt.interrupted` and move the task `running -> ready` (attempts remain under the cap, default 3).
- **Crash test harness at the Store seam:** a test-only hook `fail_after(n_events)` raising `SimulatedCrash`.

## Demo path
```
$ factory run --adapter fake --project fixtures/slow "sleep then create hello.txt" &   # adapter sleeps 3 s
$ sleep 1; kill -9 %1
$ factory resume R-0001
run R-0001 completed (1/1 tasks succeeded)
$ factory events R-0001 | grep -E "interrupted|started"
... attempt.started (attempt 1) ... attempt.interrupted ... attempt.started (attempt 2)
```

## Acceptance criteria
- [ ] For a baseline run of N events, crashing after **each** k in 1..N (`SimulatedCrash`) then calling `resume` yields the **same final task and run states** as the baseline and no duplicated `seq`.
- [ ] Truncating the final event line at every byte offset of that line is recovered on startup: the torn tail is removed, a warning event is not needed, and `resume` completes.
- [ ] Flipping one byte inside a middle event makes startup fail with exit 3 and a message containing that event's `seq`; the file is left byte-identical.
- [ ] A second `factory run/resume` while the first process is alive exits 4 ("run locked") without writing any event; after the first process is killed and the lease is older than TTL, resume succeeds and records `lease.acquired` with `taken_over_from`.
- [ ] The real-process `kill -9` demo above passes in CI (subprocess test), proving behaviour outside the simulated crash hook.
- [ ] A snapshot with an unknown higher schema version is refused (exit 3), never silently reinterpreted.

## Seams
**Store interface** (crash and corruption injection) and **Engine API/CLI** (resume behaviour). No test reaches into private modules.

## TDD plan
Write each test first; each must fail for the stated reason before the fix.
1. Torn tail at one fixed offset -> recovered (then generalize to all offsets with a loop).
2. Middle corruption -> exit 3 with literal expected `seq` in the message.
3. Lease: second holder refused; stale takeover event fields (literal).
4. Crash-after-k for k=1..N on the `ok` scenario; assert equality with the baseline literal final states.
5. `attempt.interrupted` emitted exactly once per interrupted attempt, never twice after two resumes.
6. Snapshot version guard.
7. Subprocess `kill -9` test (marked slow, still in default CI).

## Implementation notes
- `Store` interface (SPEC seam 3): `append(event)`, `read_all()`, `snapshot()`, `write_snapshot(state)`, `lease()`. Keep it narrow so DEC-07's SQLite alternative could implement it later.
- Time and pid sources are injected; the lease TTL is configuration with a test override (but never a magic sleep in tests).
- Recovery order on startup: lease -> read log -> truncate torn tail -> verify chain -> load or rebuild snapshot -> reconcile in-flight attempts.
- Document the on-disk format and version in `docs/events.md` (generated from the schema where possible) and add an ADR `docs/adr/0001-event-log-store.md` if DEC-07 chose the log (it clears the three-part bar: hard to reverse, surprising, real trade-off).

## Out of scope
Multi-process concurrency beyond refusal; automatic repair of middle corruption; SQLite; remote storage; log compaction/rotation.

## Decisions & questions
DEC-07 must be resolved. Open question to flag, not decide: log rotation policy (add as a follow-up issue labelled `needs-triage` if you think it matters).

## Security & failure notes
Treat state files as untrusted input on load (an agent may have written to the worktree, though the state dir is outside agent write permissions from T-08 onward): bounded line length, strict JSON parsing, reject unknown event types for the declared schema version. Lease files must not follow symlinks. Fsync failures are fatal. This ticket is a **one-way door** (on-disk format): include a format version in events and snapshot, and call it out in the PR's Merge Danger section.
