## Context
The predecessor's guardrails were heuristic hooks that fail open. This ticket turns "agents are untrusted" into tests and, where DEC-06 requires, real isolation. Read DEC-06's resolution, SPK-01's verdicts (what the harness does not enforce), and `docs/analysis/08-security-reliability-and-risk-review.md` (findings S-01..S-13). Every finding gets a test here or an explicit accepted-risk entry.

## What to build
- **Container verification runner** (optional extra, enabled by `isolation: container`): runtime docker or podman, image from config, **no network by default**, read-only mounts except the worktree, scrubbed environment, resource limits, timeout. Required for autonomy L3/L4 (DEC-06 default).
- **Engine-side path hardening:** reject write sets and artifact paths with `..`, absolute paths or symlink escapes; never follow symlinks that leave the worktree when hashing, diffing or copying; agents cannot write under `.factory/state/` (policy deny, tested).
- **Security fixture suite** (all offline, using the fake adapter and real git/subprocess): path traversal in a plan; symlink to a file outside the worktree; planted `.git/hooks/*` in a worktree (must not run); attempt to read `.env`; environment leak attempt; network egress attempt from verification (container: blocked; host: documented residual risk); oversized output flood; secret-shaped strings in artifacts (redacted); forged approval (T-09 scenarios re-run); prompt-injection text in request, spec, plan and finding fields (no capability change); agent editing `.factory/project.yaml` (T-06 pinned config); agent invoking `factory approve` (denied).
- **Finding map:** `docs/security/finding-map.md` listing each of S-01..S-13 and R-01..R-11 with the test that proves it closed or an accepted-risk entry with an owner.

## Demo path
```
$ pytest -m security            # all offline security fixtures
$ factory run ... --project fixtures/hostile    # hostile fixture repo: hooks, symlinks, injection text
run blocked: policy denials recorded (7); no files outside the worktree changed; no network egress
```

## Acceptance criteria
- [ ] Each fixture above exists with an assertion that the **harmful effect did not occur** (file absent, marker not written, egress refused), not merely that an error was logged.
- [ ] A symlink in the worktree pointing outside it is never followed by hashing, diff, or copy code (test plants a sentinel file outside and asserts it is untouched and unread).
- [ ] With `isolation: container`, a verification command that tries to reach the network fails; with host isolation and `unsafe_host_verify: true`, the run records the residual risk in `run.created`.
- [ ] Autonomy L3 or L4 without container isolation is refused at run start (exit 2, message cites DEC-06).
- [ ] `docs/security/finding-map.md` has a row for every S-/R- finding; no row says "TBD"; every closed row links a test id.
- [ ] Output flood (agent prints 500 MB) is truncated at the configured cap, the run records `output.truncated`, and memory stays bounded (assert on the recorded size, not on RSS).

## Seams
**Engine API/CLI** and the **Policy decision function**; container runner exercised through the engine with a stub runtime executable on PATH for CI (a real container test is tagged `container`, nightly).

## Implementation notes
- Build container argv as arrays; no shell. Pin the image by digest in docs; do not pull at run time without an explicit flag.
- The security suite is marked `security` and runs in default CI (it is offline and fast).
- Keep each fixture tiny and named for the finding it proves.

## Out of scope

## Decisions & questions

## Security & failure notes
This ticket is the proof that the design holds. Do not weaken a test to make it pass; if a fixture exposes a real hole, fix the engine or record it as an accepted risk with an owner and open a follow-up issue labelled `risk:security`.
