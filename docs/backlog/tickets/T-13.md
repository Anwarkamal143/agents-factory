## Context
The first adapter that talks to a real model. It is the only ticket that needs live credentials, so it is `mode:HITL` for the live run (a human provides access and watches the first real execution). Everything else about it is built test-first against recorded transcripts. Read SPEC-01 "Adapter contract" and "Policy and autonomy", the **SPK-01 verdict table** (which permission controls the harness really enforces) and the **SPK-02 capabilities draft** (structured output, cancel, resume). DEC-02 names the harness.

## What to build
- `adapters.<harness>` implementing the T-12 interface: launch via subprocess with **argv arrays**, a minimal allow-listed environment (the harness auth variable is passed by **name** from config, never logged), working directory = task worktree.
- **Context bundle:** write `task-input` as a JSON file plus prompt text from the role asset; inline skill text unless SPK-02 showed native skill delivery works.
- **Permission mapping** driven by SPK-01: controls the harness enforces are translated from the task's permission profile (e.g. allow/deny lists); controls it does **not** enforce are enforced by the engine (process allow-list, path checks) and recorded as `capability.degraded` with the autonomy consequence (T-12 rules).
- **Structured output:** native schema mode if SPK-02 says it is reliable (>=19/20), else prompt-JSON; engine repair-once (T-04).
- **Cancel:** documented interrupt then process-group kill; **usage:** map reported tokens to `usage`, or degrade `usage`.
- `capabilities.json` committed from SPK-02; `factory doctor` probes binary presence and version.
- **Contract suite** (T-12) parameterized with this adapter, tagged `real`.
- Transcript capture to artifacts with secret redaction; fixture-repo task: add a function plus a test in a tiny repo.

## Demo path
```
$ factory doctor                         # harness binary + version ok

```

## Acceptance criteria
- [ ] The T-12 contract suite passes against this adapter (real-tagged, run manually/nightly; CI default run uses a **recorded-transcript replay** of one session to prove parsing and mapping without credentials).
- [ ] A fixture task completes end to end: engine-run verification passes on the agent's changes; the transcript artifact exists with `sha256` recorded.
- [ ] Permission denial: a prompt instructing the agent to write outside the worktree results in **no file outside the worktree** and a recorded denial (harness block or engine policy decision); the test asserts the file does not exist.
- [ ] Cancel mid-run leaves no child process (pid check) and the attempt is `interrupted` with reason `canceled`.
- [ ] Environment scrub: a planted `FAKE_SECRET` in the parent env is absent from the agent process environment (checked via a harmless prompt/echo of env names).
- [ ] Every control SPK-01 marked `not enforced` appears as a `capability.degraded` event with its autonomy consequence; none is silently ignored.
- [ ] Redaction test: a secret-shaped string in the transcript is replaced before the artifact is written.

## Seams
**Adapter contract** (suite) and **Engine API/CLI**. Recorded-transcript replay is the only test double (an adapter-level fake process).

## Implementation notes
- Never interpolate task text into a shell string. Never pass the whole environment. Pin the minimum harness version in `doctor` and fail clearly below it.
- Keep harness-specific details inside this package; the engine must not learn the harness name.
- Record exact CLI flags and versions in `docs/adapters/<harness>.md`.

## Out of scope

## Decisions & questions
DEC-02, SPK-01, SPK-02 must be closed. If SPK-01 found that **no** permission control is enforced in headless mode, stop and add `status:needs-decision`: autonomy for this adapter must be capped at L1 and the maintainer should confirm before you proceed.

## Security & failure notes
This adapter hands real credentials to a process that executes model-chosen actions. Auth by variable name only, never in argv; redact in logs; the worktree is the only writable path at the engine level regardless of harness behaviour (verify with the denial test). Network posture follows SPK-01; if network cannot be disabled, say so in capabilities and cap autonomy.
