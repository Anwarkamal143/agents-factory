## Context
The predecessor never validated its config (the schema file was documentation only) and its readiness check accepted any non-blank command, so `["true"]` passed. Configuration here is schema-validated at load and verification commands are linted. Read SPEC-01 "Verification" and DEC-06's resolution.

## What to build
- Full `project.yaml` schema (`factory.project/1`): `base_branch`, `verify[{name, argv, timeout_s, env_allow}]`, `adapter`, `autonomy` (L0-L4), `policy` overrides, `budgets`, `unsafe_host_verify`.
- **Layered config:** defaults -> policy pack -> optional org file -> project file -> CLI flags; `factory config explain <key>` prints value and source layer.
- **Verification lint** rejects: empty argv; executables `true`, `false`? (`false` always fails, flag as suspicious), `:`; `sh -c true`, `bash -c "exit 0"`; commands consisting only of `echo`; duplicate check names. Message names the rule.
- **`factory doctor`** (read-only): checks `git` version, harness binary presence (if configured), that every `verify` command **passes on the clean base** (runs them in a temporary copy, never touching the working tree), and prints degradations. If autonomy >= L2 and verification is not container-isolated and `unsafe_host_verify` is not true, doctor and `run` **refuse** (DEC-06 default).
- **Pinned config:** the effective configuration is resolved **once at run start from the trusted project root (the base commit), its sha256 is recorded in `run.created`, and the engine never re-reads `.factory/**` from a task worktree.** An agent that edits config inside its worktree therefore cannot change how it is verified.
- **Scrubbed environment:** verification subprocess receives only `env_allow` names (default `PATH`, `LANG`, `CI`); everything else absent.

## Demo path
```
$ factory doctor
git 2.4x ok | verify[unit] passes on base | verify[lint] passes on base
autonomy L2 requires isolation: set unsafe_host_verify: true or use a container   # exit 1 if neither
$ factory config explain autonomy
L2  (source: project.yaml)
```

## Acceptance criteria
- [ ] Each lint rule has a failing fixture and a clear message: `verify: ["true"]`, `["sh","-c","true"]`, `["echo","ok"]`, empty list, duplicate names all exit 2.
- [ ] A config with an unknown top-level key, a wrong type, or `autonomy: L9` is rejected with exit 2 naming the JSON path.
- [ ] `factory config explain` reports the correct source layer for a value set in defaults, project, and CLI flag (three literal cases).
- [ ] A planted `FAKE_SECRET=not-real` in the parent environment is **not** visible to a verification command that prints its environment; a name listed in `env_allow` is visible.
- [ ] `doctor` reports a verify command that fails on the clean base as an error, and does not modify the working tree (hash the tree before and after).
- [ ] **Self-grading test:** the fake agent edits `.factory/project.yaml` in its worktree to set `verify` to `["true"]`; the engine still runs the original verify commands (asserted by the verification event's `argv`), and `run.created` carries the config hash.
- [ ] Autonomy L2 without isolation and without `unsafe_host_verify` is refused with a message that names DEC-06 and how to proceed.

## Seams
**Engine API/CLI** (`doctor`, `config explain`, `run` refusal) and **Schemas** (config fixtures).

## Implementation notes
- YAML loaded with `safe_load` only; reject YAML tags and anchors that create objects.
- Lint is a list of small named rules, each with a docstring and a fixture; adding a rule never changes others.
- `doctor` is strictly read-only; any temp copy lives under the OS temp dir and is deleted afterwards.

## Security & failure notes
No shell. No environment values in logs or events (names only). Config files are untrusted input in target repos: size and depth limits; never `eval`. Timeouts mandatory on every verify command (default 300 s).
