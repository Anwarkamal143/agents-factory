## Context
The predecessor's debugging depended on reading PR comments and worktrees; it had no structured trace or cost accounting. The event log already holds the truth; this ticket makes it usable. Read SPEC-01 "Event log and store".

## What to build
- **`factory explain <run>`:** walks the log backwards from the first blocking or failing transition and prints the causal chain (transition, cause, verification log excerpt, budget state, any policy denial) plus the **next command** to run (`resume`, `approve`, edit spec, ...).
- **`factory events <run> [--type T] [--task ID] [--json]`** filtering.
- **`factory status <run> --usage`:** tokens, wall time and attempts per task and per role, plus totals; sums equal the sums of the recorded `usage` fields.
- **`factory export <run>`:** tarball of the log, artifacts and a **redacted** config; secrets never included.
- **`factory replay <run>`:** re-applies every event to a fresh state machine and verifies determinism (final state equals snapshot); a tampered or reordered event is reported with its `seq`.

## Demo path
```
$ factory explain R-0007
task T-3 blocked: repeated_failure (check "unit" exit 1 twice, same signature)
cause: attempt 2 produced the same failure as attempt 1 (no progress)
next:  fix the objective or edit the plan, then: factory resume R-0007
$ factory export R-0007 > run.tar.gz
```

## Acceptance criteria
- [ ] For each scenario (`always_fails_same_way`, `review_not_converging`, `budget_exhausted`, `policy_denied`, `awaiting_approval`) `explain` prints the literal causal sentence and next command listed in the test fixtures.
- [ ] `status --usage` totals equal the sum of per-attempt `usage` in the log (computed independently in the test).
- [ ] A planted `FAKE_SECRET=not-real` value never appears in the exported archive (scan every file).
- [ ] `replay` succeeds on a clean log; flipping the order of two events or editing one payload makes it fail with that event's `seq`.
- [ ] `events --type task.transitioned --task T-2 --json` outputs only matching JSON lines, valid per `event.schema.json`.
- [ ] `explain` on a completed run says so and exits 0 (no false alarms).

## Security & failure notes
`explain` prints log excerpts that may contain untrusted text; sanitize control characters and bound length. Export is the main exfiltration surface: redaction test is mandatory.
