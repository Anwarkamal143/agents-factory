## Context
Every side effect is a recorded policy decision, default-deny. The predecessor's guardrails were fail-open regex hooks; this is a pure decision function plus engine integration. Read SPEC-01 "Policy and autonomy" and DEC-03's resolution (default level and approval channel).

## What to build
- `decide(action, context) -> allow | deny | needs_approval(reason)` (pure, no I/O).
- **Actions:** `fs.read`, `fs.write`, `net.connect`, `proc.spawn`, `secret.read`, `git.write`, `deliver.merge`, `task.accept`, `spec.approve`, `plan.approve`, `approval.grant`.
- **Context:** actor (`agent|engine|human`), autonomy level, permission profile, detected risk classes, lines changed.
- **Risk classification** from changed paths (globs configurable in project config; defaults): `schema` = `**/migrations/**`, `**/*.sql`; `dependencies` = `package.json`, `pyproject.toml`, `requirements*.txt`, lockfiles; `ci-config` = `.github/workflows/**`; `auth` = paths containing `auth`, `login`, `session`, `token` (heuristic, overridable); `secrets` = `.env*`, `**/*.pem`, `**/*.key`; `money` = `**/billing/**`, `**/payment*/**`; `size` when lines changed > `size_lines` (default 400).
- **Decision matrix** (literal; tests assert every cell):
| Action (actor) | L0 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|---|
| `fs.write` in own worktree (agent) | deny | allow | allow | allow | allow |
| `task.accept` | deny | needs_approval | allow | allow | allow |
| `spec.approve` | deny | needs_approval | needs_approval | needs_approval | allow |
| `plan.approve` | deny | needs_approval | needs_approval | allow | allow |
| `deliver.merge` (engine), no risk class | deny | needs_approval | needs_approval | allow | allow |
| `deliver.merge`, any risk class present | deny | needs_approval | needs_approval | needs_approval | needs_approval only if class in `always_human` (default `[secrets]`) else allow |
- **Always (any level):** `approval.grant` is allowed only for actor `human`; agent `net.connect` is deny unless the profile says otherwise; agent `secret.read` is deny unless the secret name is in the profile; `fs.write` outside the worktree and `git.write`/`deliver.merge` by an agent are deny; unknown action => deny.
- **Permission profile** generation: from role + autonomy build the `permissions` object for `task-input` (`fs.write` paths, `net`, `shell` argv-prefix allow-list, `secrets`).
- **Engine integration:** every side effect calls `decide` and appends `policy.decision {action, actor, decision, reason}`; `needs_approval` creates the hook point used by T-09.

## Demo path
```
$ factory policy explain --level L2 --action deliver.merge --risk schema
needs_approval (risk class schema requires a human at L2)
$ factory policy explain --level L3 --action deliver.merge
allow
```

## Acceptance criteria
- [ ] Table-driven test covers **every cell** of the matrix above (6 actions x 5 levels, plus the risk-class row variants) with literal expected decisions.
- [ ] Unknown action and unknown autonomy level both yield `deny` (not an exception).
- [ ] `approval.grant` by `agent` or `engine` is `deny`; by `human` is `allow` at every level.
- [ ] Risk classification table: each default glob maps a sample path to the expected class (one positive and one negative sample per class); changed-lines 400 is not `size`, 401 is.
- [ ] Every side effect in a run (verify spawn, workspace write, adapter start) produces exactly one `policy.decision` event before it happens (asserted by ordering in the log).
- [ ] Generated permission profile for role `builder` at L2 contains the worktree path as the only writable path, `net: false`, and **does not** include the `factory` executable in `shell`.

## Seams
**Policy decision function** (primary, pure) and **Engine API/CLI** (events and refusal behaviour).

## TDD plan

## Implementation notes
- Keep the matrix as data (a table in code or a policy YAML shipped in `policies/`), with a test that loads it and compares to the literal expectations; adding a row requires adding a test row.
- `decide` must not read files or the environment.
- Policy results are cached per run only if identical inputs; never across runs.

## Security & failure notes
Default-deny, fail-closed: any exception inside `decide` becomes `deny` plus an error event. Never let a profile widen permissions beyond the role default. The matrix is a **risk surface**: PR must flag it (door: two-way, blast radius: all side-effect gating).
