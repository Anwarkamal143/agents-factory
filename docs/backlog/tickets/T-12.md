## Context
Harness neutrality is only real if one test suite can run against any adapter. This ticket freezes the five-operation contract and builds the suite plus the engine's capability negotiation. Read SPEC-01 "Adapter contract" and "Contracts: adapter capabilities".

## What to build
- Formal adapter interface: `capabilities()`, `start(task_input) -> handle`, `events(handle)`, `cancel(handle, grace_s)`, `result(handle)`, optional `resume(token)`; `capabilities.json` schema.
- **Engine negotiation rules** (each emits `capability.degraded` with the rule applied):
  - `structured_output: none` => prompt-for-JSON, engine validates, repair-once (T-04).
  - `cancel: false` => engine kills the process group after `grace_s`.
  - `resume: false` => restart the attempt from the last checkpoint artifact.
  - `usage: false` => budgets enforced on wall time and tool calls only.
  - `sandbox: none` => policy **caps autonomy at L1** (event shows the cap).
  - `skills: none` => skill text inlined into the prompt.
  - `hooks: false` => warning only (hooks are defense in depth).
  - `ask_user: false` => unanswered questions move the task to `blocked` (needs input).
- `factory adapter list` and `factory adapter probe <name>` print capabilities and active degradations.
- **Contract suite** parameterized by an adapter factory: `capabilities` validates the schema; `start` returns a handle; `events` ends with exactly one terminal event; `result` validates `task-result`; `cancel` stops work within the grace period and is idempotent; `result` before completion errors clearly; malformed/slow/crash behaviours surface as defined statuses, not exceptions.
- Two fake variants: `fake` (all capabilities on) and `fake-minimal` (all off) both pass the suite.

## Demo path
```
$ factory adapter probe fake-minimal
structured_output: none -> degraded (prompt-json + repair-once)
sandbox: none -> degraded (autonomy capped at L1)
cancel: false -> degraded (process-group kill)
```

## Acceptance criteria
- [ ] The contract suite passes for `fake` and `fake-minimal`.
- [ ] A deliberately broken adapter fixture (e.g. `result` returns a dict missing `status`) **fails** the specific named contract tests (the suite demonstrably can fail).
- [ ] `probe fake-minimal` output contains one degradation line per rule above (literal expected text per capability).
- [ ] With `sandbox: none` and project autonomy L3, the run starts at L1 and the event log has `capability.degraded` with `autonomy_cap=L1`.
- [ ] With `ask_user: false` and a spec question from the adapter, the task is `blocked` (needs input), not hung.
- [ ] Running the same scenario against `fake` and `fake-minimal` yields the same final states (capabilities change mechanisms, not outcomes).

## Seams
**Adapter contract** (primary) and **Engine API/CLI** (negotiation visible in events).

## TDD plan
1. Capability schema fixtures.
2. Contract test for `events` terminal event (first against `fake`).
3. Broken adapter fixture fails.
4. One degradation rule at a time, each with its literal event.
5. Autonomy cap integration.
6. Same-outcome parity test.

## Implementation notes
- The suite lives in `tests/adapters/` and exports `run_contract_suite(make_adapter)` so T-13/T-24 reuse it unchanged; mark real-adapter parametrization with the `real` tag.
- Degradation is data: a table mapping capability value -> mechanism -> event text; one place to read.

## Out of scope

## Decisions & questions
None blocking. Any contract change after this ticket needs a new contract major version (see SPEC).

## Security & failure notes
Sandbox degradation must fail **closed** (cap autonomy), never open. An adapter that lies about capabilities is detected only by tests; document that the contract suite is the trust mechanism.
